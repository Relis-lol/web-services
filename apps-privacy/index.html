Shopify Apps Privacy Policy

Saveroq Studio operates several independent Shopify apps. This page has two parts: information that is common to all of them, and — below — a dedicated section for each individual app that describes what that specific app actually accesses, stores, and does not store. Apps differ from one another in the scopes they request and the data they touch; nothing on this page should be read as implying that every Saveroq app requests the same permissions or handles data the same way. Only the section for a specific app describes that app's actual practices.

Purpose of processing

Each Saveroq Shopify app is installed by a merchant into their own Shopify store to perform one specific, narrowly scoped task inside Shopify Admin or the merchant's storefront theme. Processing exists only to make that app's own feature work. Saveroq does not sell or rent merchant or customer data, share it for advertising or marketing, or use it to build advertising profiles. Processors or service providers that are necessary to provide an app's service may process data only for that purpose on Saveroq's behalf. Details are stated in the app-specific section below.

Legal basis

Processing described on this page relies on Art. 6(1)(b) GDPR (performance of the contract formed when a merchant installs the app through Shopify) for the technical session and API-access data each app needs to function, and on Art. 6(1)(f) GDPR (legitimate interest in operating a secure, functioning app) where processing is needed for security, abuse prevention, or basic technical operation and is not itself part of that contract. If a specific app's section below states a different or additional legal basis, that section governs for that app.

Recipients

Data described on this page is processed within Shopify's platform — Shopify itself acts as a data processor under the merchant's own agreement with Shopify — and, where an app's own section below says it stores data, on infrastructure controlled by Saveroq. Necessary technical processors or service providers may be involved only to provide the app service; they are identified in the relevant app-specific section. Saveroq does not sell or pass this data to advertising or marketing providers. Each app's section states whether that app uses any analytics, advertising, or error-tracking service.

Shopify authentication and session handling

All Saveroq Shopify apps use Shopify's standard OAuth / App Bridge authentication flow. Each app stores the minimum session data required by the Shopify app framework it is built on — typically the shop domain and an access token — so it can make authorized Shopify API calls on the merchant's behalf between page loads. This technical session data is separate from any app-specific data described in that app's own section below; some apps store nothing beyond it.

Cookies

Saveroq's Shopify apps do not set their own analytics or advertising cookies. Any cookie set during Shopify's embedded-app authentication flow (for example to maintain state while logging in) is set and controlled by Shopify's own app framework, not by Saveroq's app code.

Hosting

Saveroq's Shopify apps run on Saveroq-operated server infrastructure. Hosting details specific to an individual app are listed in that app's own section below, where they have been verified.

International data transfers

Shopify operates its platform globally; processing that Shopify itself performs as platform operator may involve transfers outside the EU/EEA under Shopify's own privacy policy and safeguards, which are outside Saveroq's control. Any processors or service providers used by Saveroq, along with the relevant hosting location and processing details, are identified in the app-specific section below where applicable (see "Recipients" above).

Merchant privacy requests

To ask what data an installed Saveroq app holds about your store, or to request its deletion, contact kontakt@saveroq.com. Uninstalling an app from Shopify Admin also triggers that app's own uninstall cleanup, described in its section below.

CartLink Lite

  • Purpose: Lets merchants and their storefront customers generate a Shopify cart permalink — a standard Shopify URL that reopens a specific set of items in the cart — either from Shopify Admin (Cart Link Builder) or from a "Share Cart" button on the storefront cart page.
  • Shopify access scopes: read_products only. No scope for orders, customers, draft orders, or store settings is requested.
  • Data accessed: Product and variant data, read via the Shopify Admin GraphQL API under the read_products scope, to re-check that selected items are still available immediately before a link is generated. On the storefront, the Share Cart button reads the shopper's own current cart client-side through Shopify's Ajax Cart API (/cart.js) — this happens in the shopper's browser, not on Saveroq's server.
  • Data stored: Nothing beyond the standard Shopify session record (shop domain and access token) required to run as an embedded Shopify app.
  • Data not stored: Cart contents, generated cart links, order data, customer names, emails or addresses, and click or usage analytics. In the Cart Link Builder, line items exist only in the browser for the duration of the admin session; the generated link is the only output, and it is not written to any Saveroq database.
  • Authentication/session data: Standard Shopify session data (shop domain, access token) is stored in the app's session table (Prisma / PostgreSQL), as required by the Shopify app framework the admin app is built on.
  • Analytics/tracking: None. CartLink Lite does not load or call any analytics, advertising, or error-tracking service.
  • Retention/deletion: Session data is retained only for as long as the app remains installed on a shop. There is no cart, link, or order history to retain in the first place.
  • Uninstall behavior: Uninstalling the app deletes its stored session record for that shop. Shopify's mandatory compliance webhooks (customers/data_request, customers/redact, shop/redact) are implemented and verified: because no customer data is ever stored, the data-request and customer-redact webhooks confirm there is nothing to return or erase, and shop/redact removes any remaining session record as a defensive second pass 48 hours after uninstall.
  • Protected customer data: CartLink Lite does not request or use Shopify protected customer data.
  • Production app URL: https://cartlink.saveroq.com
  • Contact for privacy requests: kontakt@saveroq.com

Metafield Cleaner Lite

  • Purpose: Lets merchants scan Product and Product Variant metafields, inspect values that have no current metafield definition, export those values as CSV or JSON, and selectively delete eligible values after explicit review and confirmation. The app does not claim that a value without a definition is unused or was left by an uninstalled app.
  • Shopify access scopes: write_products only. Shopify includes the corresponding product read capability in this write scope. No customer, order, company, checkout, theme, file, or discount scope is requested.
  • Data accessed: Product and Product Variant identifiers and titles; metafield namespace, key, type, and current value; and Product/Product Variant metafield-definition metadata. The app uses Shopify's Admin GraphQL API only.
  • Data stored: Standard Shopify session data; shop-scoped scan status and summary counts; a small set of example Shopify owner identifiers for each scan group; and deletion audit metadata containing namespace, key, owner type, requested/deleted/failed counts, status, error text where applicable, and timestamp.
  • Data not stored: Metafield values and product or variant titles are fetched live for review, export, or deletion and are not persisted in Saveroq's database. Export files are generated on request and are not retained by Saveroq. The app stores no customer, order, checkout, payment, theme, or storefront visitor data.
  • Authentication/session data: Standard Shopify session data, including the shop domain and access token, is stored in the app's Prisma/SQLite session table so the embedded app can make authorized Shopify API calls.
  • Hosting and processor: Production is hosted on Saveroq-controlled Hetzner infrastructure in Germany. Hetzner acts as the technical hosting and infrastructure processor. HTTPS/TLS protects data in transit, and the app's persistent database and backups remain isolated from other applications on the server.
  • Analytics/tracking: None. Metafield Cleaner Lite does not load or call any analytics, advertising, or behavioral tracking service.
  • Retention/deletion: Session, scan-summary, and deletion-audit data is kept only while needed to operate the installed app. The shop/redact compliance webhook deletes all rows stored for the shop. Operational SQLite backups use short rolling retention and expire with the same infrastructure policy.
  • Uninstall behavior: The app/uninstalled webhook removes active session credentials. Shopify's mandatory compliance webhooks (customers/data_request, customers/redact, and shop/redact) are authenticated and implemented; the customer-specific hooks have no customer data to return or erase, and shop/redact removes remaining session, scan, and deletion-audit rows.
  • Protected customer data: Metafield Cleaner Lite does not request or use Shopify protected customer data.
  • Production app URL: https://metafield-cleaner.saveroq.com
  • Contact for privacy requests: kontakt@saveroq.com

Variant Gallery Lite

  • Purpose: Variant Gallery Lite lets merchants assign existing Shopify product images to the values of one product option. Its Theme App Extension then shows the mapped images for the option value selected on the storefront. The app does not generate or upload images.
  • Shopify access scope: The app requests only write_products. Shopify includes the corresponding product read access in that scope so the app can display and update the product data needed for image mappings. The app requests no customer, order, company, checkout, payment, fulfillment, or marketing scopes.
  • Product data accessed: The app accesses product identifiers, titles, handles, status, options and option values, variants and selected options, product media/image identifiers, image URLs and alt text, and its own app-owned mapping metafield. It also receives Shopify product-deletion notifications so obsolete local quota records can be removed.
  • Data stored in Shopify: The option-to-image mapping is stored as JSON in the app-owned product metafield app.variant_gallery_map. The mapping contains the selected option name, option values, and the ordered Shopify media identifiers assigned to those values. Shopify stores this metafield with the product.
  • Data stored by Saveroq: The app stores the shop identity and standard Shopify session/authentication records needed to operate the installation, including the granted scope, access credentials, and expiry information. Shopify's session format may also contain authenticated merchant-account metadata supplied during authorization. For plan enforcement and concurrency safety, the app stores configured product identifiers, quota status, temporary reservation tokens, and reservation expiry timestamps. It does not persistently duplicate product titles, variants, images, option values, or the mapping JSON outside Shopify.
  • Data not requested: Variant Gallery Lite does not request or store Shopify protected customer data such as customer names, email addresses, phone numbers, postal addresses, order records, or payment details. It does not collect customer-uploaded photographs.
  • Authentication: Shopify OAuth/session credentials are used solely to authenticate the shop and perform the authorized product and metafield operations. They are not shared with merchants or storefront visitors.
  • Billing: The Free plan supports up to three configured products. The Unlimited plan is priced at USD 4.99 per 30 days. Subscription purchase and payment processing are handled by Shopify; Saveroq does not receive or store card or bank-account credentials. The app reads the shop's current Shopify app-subscription status to determine plan access.
  • Storefront behavior, cookies, and tracking: The Theme App Extension uses product, variant, media, and mapping data rendered by Shopify in the visitor's browser. It does not send storefront-visitor data to Saveroq, set cookies, use local or session storage, run advertising or profiling, or include Saveroq analytics or tracking pixels.
  • Hosting and processor: Production is hosted on Saveroq-controlled Hetzner infrastructure in Germany. Hetzner acts as the technical hosting/infrastructure processor. HTTPS/TLS protects data in transit. The app uses its own isolated SQLite database volume, separate from the databases and storage of other Saveroq apps.
  • Retention and deletion: Local Shopify session/authentication records and active configured-product/quota records have no separate fixed time-to-live and are retained while the app is installed and they remain operationally required. A pending quota reservation is valid for five minutes; its row is released or converted to an active record during the next product reconciliation. A product-deletion webhook removes the corresponding configured-product record. The app-uninstalled webhook removes the shop's local sessions and configured-product records. The shop-redact webhook performs the same local cleanup. No separate accounting or tax retention period is applied to these operational app records.
  • Backups: A daily production job creates SQLite online backups, runs a PRAGMA quick_check integrity check, verifies each compressed snapshot, and stores it in an app-specific root-only backup directory. Production backups are retained for 30 days. Backup creation, integrity verification, and restore into an isolated disposable volume have been tested successfully.
  • Uninstall and Shopify metafields: The app attempts a best-effort deletion of its app-owned mapping metafields during Shopify's delayed shop-redact processing when usable Shopify credentials are still available. This cannot be guaranteed after Shopify has revoked the access token. Independently, Shopify deletes the app-owned metafield definition when the app is uninstalled and may temporarily retain the metafield values without a definition while asynchronous cleanup runs. Shopify does not document a guaranteed cleanup period. If the same app is reinstalled during Shopify's retention window, Shopify may recreate the definition and reassociate retained values under new definition identifiers.
  • Privacy webhooks: The app handles Shopify's mandatory customer-data-request, customer-redact, and shop-redact topics. Because the app does not hold customer data, customer-specific requests are acknowledged without returning or deleting customer records. Shop-redact removes the shop's local app records and performs the metafield cleanup attempt described above.
  • Protected customer data: The app does not request protected customer data access, so Shopify Protected Customer Data approval is not required for its current functionality.
  • Production app URL: https://variant-gallery.saveroq.com
  • Contact for privacy requests: kontakt@saveroq.com

EU E-Invoice

  • Purpose: EU E-Invoice converts eligible Shopify orders into structured electronic invoices and related correction documents. Depending on merchant configuration, output is XRechnung XML, ZUGFeRD / Factur-X PDF/A-3, or both. Unsupported or inconsistent cases are blocked instead of being issued automatically.
  • Shopify access scopes: read_companies, read_customers, read_orders, and read_returns.
  • Protected customer data: Name and address only. Customer email and phone are not requested for current functionality.
  • Data accessed: Buyer or company name; billing address; Shopify order identifiers; line items; quantities; prices; discounts; shipping charges; tax information; payment status; company and company-location information; tax-registration information where available; order changes relevant to invoicing; and refund or return information relevant to supported correction documents.
  • Data not used: No customer email, no customer phone, no advertising, no profiling, no behavioral analytics, and no sale of personal data.
  • Data stored: Invoice source snapshots; normalized invoice data; issued invoice and correction records; validation results; hashes; XRechnung and ZUGFeRD artifacts; evidence records; webhook and job metadata; and pseudonymized security and access logs.
  • Purpose of processing: To generate, validate, issue, store, retrieve, reconcile, and, where supported, correct electronic invoices on behalf of the merchant.
  • Validation: XRechnung documents are validated using KoSIT. ZUGFeRD / Factur-X documents are validated using pinned Mustangproject and veraPDF tooling. Validation runs on Saveroq-controlled infrastructure; customer data is not sent to an external validation SaaS.
  • Hosting and processor: Production is hosted on Saveroq-controlled Hetzner infrastructure in Germany. Hetzner acts as the technical hosting and infrastructure processor for provision of the service. HTTPS/TLS protects data in transit, protected production data is encrypted at rest, and production and development are separated.
  • Backups: Protected data is included only in the encrypted backup and recovery process.
  • Access: Administrative access follows least-privilege principles. Access to protected data is pseudonymously logged. Saveroq does not routinely inspect merchant customer data manually.
  • Retention: Issued invoice and correction data is retained on behalf of the merchant for applicable statutory or contractual retention periods. For German invoices, the confirmed invoice-retention period is eight years, beginning at the end of the calendar year in which the invoice was issued. Operational data is retained only as long as necessary for operation, security, troubleshooting, or legal obligations.
  • Privacy webhooks: Shopify's mandatory compliance webhooks (customers/data_request, customers/redact, and shop/redact) are implemented. Privacy requests are handled according to applicable retention requirements; data that must still be retained for statutory invoice obligations is not deleted automatically.
  • Uninstall behavior: Shopify API and session access stops, session credentials are removed, and operational data is removed according to the retention policy. Issued fiscal documents and evidence may remain solely for required retention.
  • Analytics/tracking: No advertising or behavioral tracking.
  • Production app URL: https://einvoice.saveroq.com
  • Contact for privacy requests: kontakt@saveroq.com

Saveroq Compliance Hub

  • Purpose: Saveroq Compliance Hub helps merchants maintain product-compliance information, assess whether configured information is complete, manage supporting evidence, and publish selected product information. Readiness findings identify missing or inconsistent information; they are not a certification, guarantee of legal compliance, or legal advice.
  • Shopify access scopes: read_products, write_products, read_metaobjects, and write_metaobjects.
  • Shopify data accessed: Product and variant identifiers, titles, handles, product type, vendor, status, images, SKU, barcode, and update timestamps. The app reads and writes its custom disclosure metaobjects and product disclosure references only through a merchant-initiated preview and apply workflow. It also receives app-lifecycle, scope, product, bulk-operation, and mandatory privacy webhooks.
  • Data stored: Shop identifiers and domain; Shopify sessions and access tokens; installation, retention, and subscription state; relevant product and variant catalog attributes; synchronization, job, and webhook-deduplication records; manufacturer and responsible-person records; profile assignments, applicability rules, product identifiers, localized English and German safety information, evidence metadata, readiness findings, disclosure projection identifiers and hashes, public-page state and opaque identifiers, and redacted or hashed audit details.
  • Data not requested: The app does not request Shopify customer, order, payment, checkout, or theme data and does not request access to Shopify protected customer data. Customer records are not intentionally stored.
  • Authentication and billing: Shopify OAuth sessions and access tokens are used to authenticate the merchant and call the Shopify Admin API. Partner API credentials are used only on the server for entitlement and subscription verification and are not delivered to the merchant's browser. The Standard plan is USD 14.99 per 30 days with a 14-day trial through Shopify App Pricing. Shopify processes the charge; the app does not receive card data.
  • Evidence files: Merchants may upload PDF, PNG, or JPEG evidence files up to 10 MiB. The app validates the file extension, media type, file signature, size, safe filename, opaque storage key, and SHA-256 hash. Production requires a successful ClamAV scan before a file can be approved. Files are stored in an app-owned persistent volume outside the public web root, and private downloads require an authenticated, tenant-scoped request.
  • Evidence visibility: Evidence is classified as PUBLIC, MERCHANT_INTERNAL, or AUTHORITY_ONLY. Internal and authority-only evidence and evidence quotations are excluded from public-page data. A clean file classified as public can be offered through a controlled public download only while its related public page is explicitly published. Superseded evidence no longer counts toward readiness.
  • Public product pages: A merchant can explicitly publish an opaque /p/<id> URL only after the configured readiness checks pass. Public output is limited to the product name, image and identifier; applicable public manufacturer and responsible-person contact details; approved English and German safety statements; and the update time. It excludes sessions, internal notes, non-public evidence, evidence quotations, audit and job details, and database identifiers. The merchant can revoke a page. Generated QR codes contain only the public HTTPS URL.
  • Hosting and service providers: The application, PostgreSQL database, worker, ClamAV scanner, and evidence volume run in isolated containers on Saveroq-controlled Hetzner infrastructure. HTTPS/TLS protects traffic. Shopify provides commerce-platform data, authentication, Admin API, webhooks, and app-pricing services. Cloudflare provides authoritative DNS for the production hostname; the record is DNS-only and Cloudflare does not proxy the application's traffic.
  • Security: Controls include tenant isolation, authenticated and scoped access, server-side secrets, webhook HMAC verification and deduplication, restricted networks, an application database that is not exposed to the public internet, audit hashing, and redaction of common secret fields and token patterns from audit serialization.
  • Analytics, cookies, and tracking: No separate analytics, advertising, or behavioral-tracking service is integrated. The embedded app uses Shopify's authentication and session infrastructure for essential operation.
  • Retention: While the app is installed, configuration, catalog, evidence, audit, and operational records are retained until the merchant deletes them or a lifecycle event removes them. After uninstall, sessions are deleted immediately, access stops, public pages are revoked, and tenant database and private-evidence deletion is scheduled after the production default of 30 days. Reinstalling during that period cancels the scheduled deletion. A valid Shopify shop/redact request deletes tenant database rows and private evidence immediately and idempotently.
  • Backups: PostgreSQL data and evidence files are backed up daily and retained for 30 days with restricted permissions and SHA-256 integrity manifests. Deletion requests are reapplied after a restore so restored data does not bypass a deletion obligation.
  • Privacy webhooks: Shopify's mandatory privacy webhook topics are handled. Because the app does not intentionally store customer records, customer-specific requests do not return or delete customer records; shop-redact performs the tenant deletion described above.
  • Production app URL: https://compliance.saveroq.com
  • Contact for privacy requests: kontakt@saveroq.com
